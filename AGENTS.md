## Remote Session Safety

- `opencode-ssh` automatically includes `opencode-ssh-remote-use/opencode-ssh-safety.md` in the root and every direct child session's instructions; remote projects do not need a copy or an `AGENTS.md` reference.
- Package code requires the root and every direct child to call package `remote_status` before package project tools or root Task. The tool internally runs and validates exact `hostname; whoami; pwd -P` in the canonical launch workdir and completes preflight atomically. Parent evidence is not transferable.
- Every `remote_status` attempt advances a per-session generation. A new generation invalidates prior preflight and aborts active package project SSH/SFTP/mutation leases; denied, failed, canceled, non-zero, truncated, malformed, or mismatched checks leave package project tools and root Task blocked until a new `remote_status` fully succeeds. Completed remote commits and already-admitted upstream Task execution are not retroactively undone. Package Bash is not a preflight mechanism, and built-in `explore` package Bash remains unavailable after preflight.
- In an ordinary local checkout without an expected SSH session, remote preflight does not apply. The injected safety file is prompt/operator guidance; the state gates above are package enforcement, and OpenCode permission evaluation is host policy.

## Runtime Shape

- `src/cli.ts` provides `opencode-ssh <ssh-alias> <absolute-remote-workdir>` and `opencode-ssh self-test`; it does not forward OpenCode arguments.
- Every real launch runs the isolated OpenCode loader probe before starting SSH. `self-test` runs that same local probe without a target.
- The launcher starts a system OpenSSH ControlMaster, resolves the canonical remote workdir, injects the safety-instruction path and package-root server plugin through `OPENCODE_CONFIG_CONTENT`, requires a nonce-protected ready handshake, and supervises cleanup.
- The production OpenCode host inherits stdin/stdout for its normal TUI. Host fd 2 is a pipe drained by the launcher and is not inherited by the terminal. The launcher retains the exact first 1 MiB delivered to it before pipe closure, not all bytes ever written; source-unit exactness covers only bytes delivered to `accept`, while launcher integration and real default-TUI/PTY evidence are separate. The visual gate remains pending.
- Raw host-stderr capture is always enabled by explicit product decision. Persistence is never per answer/chat: a non-empty capture may be published only after the entire TUI exits, the whole OpenCode process is confirmed settled, and critical cleanup completes. Unconfirmed settlement discards the in-memory bytes and records a privacy-safe failure. The normal path is `${XDG_STATE_HOME:-$HOME/.local/state}/opencode-ssh/logs/raw/opencode-host-stderr-YYYY-MM-DD-<startupID>.bin`.
- Raw files are best-effort diagnostics written directly to an exclusive final filename. Write/close failure or abrupt loss can leave a partial `.bin`; operator output identifies detected partial storage, and `close` is not `fsync` or power-loss durability. Native storage starts after critical cleanup and cannot alter the selected core result, but pathological/non-local filesystem work can delay launcher process settlement without a universal cancellation or return bound.
- `src/index.ts` is the server plugin entrypoint. It overrides `bash`, `glob`, `grep`, `read`, `write`, `edit`, and `apply_patch`, and adds `remote_status`.
- Command tools use one-shot `ssh` channels through the owned socket. File tools use system `sftp` and a private launch-scoped mirror.
- Slave SSH/SFTP processes fail closed when the master socket is unavailable. They do not open a replacement connection or retry commands.
- `SyncEngine` has one abort-aware operation-wide mutex per plugin instance, per-file content baselines, canonical revalidation, owner-token remote locks, private sibling temporaries, and per-file atomic `mv -fT --`. Bash, MCP, other plugins/module instances, and non-cooperating writers bypass it.
- OpenCode loads the generic safety file through its `instructions` configuration. The system transform appends compact generated target context only. Remote root `AGENTS.md` is not auto-read or injected; a preflighted session may explicitly read it through normal permissions.
- After root preflight, the local root may use OpenCode's local Task orchestration for multiple foreground direct siblings. Effective depth remains explicit zero or one; package runtime rejects child Task and background Task, and the launcher forces the background flag false.
- Task resume is package-controlled, not general OpenCode behavior. Callable session lookup and matching selected, loader, and production runtime versions are required for every launch. Every identified version passing those checks receives the private launcher/plugin resume capability; version is diagnostic and baseline evidence, not a runtime allowlist. Generated system context states the launch decision.
- OpenCode stores global/per-agent policy separately from its optional session-local permission overlay. Package Task safety normalizes an omitted caller-root `session.permission` to `[]` for root fingerprinting and deny projection, matching OpenCode's own effective merge; this grants nothing. Explicit malformed root permissions, incompatible root-session asks, changed root evidence, and missing or malformed child permission arrays remain fail-closed.
- On a capability-enabled launch, fresh-child admission is one-shot per root/call. Registration binds the root permission fingerprint and security epoch from Task before to Task after, requires unchanged root evidence, preserves every inherited SSH-project deny, and requires the child to expose an explicit matching agent and explicit permission array.
- When enabled, resume is limited to the exact `task_id` of a successfully completed foreground direct child created by the same root in the current launch, with the same `subagent_type`. The launch-local ownership registry rejects cross-launch, foreign-root, unknown/invented, child-initiated, background, busy, failed, canceled, and uncertain resume attempts before upstream can reinterpret an unknown ID as a fresh child.
- Resume revalidates the exact launch, caller root, direct child, `subagent_type`, observed agent, root/child permissions, and security epochs before atomically reserving one caller. Once reserved, failed, missing, malformed, aborted, canceled, or uncertain admission/completion permanently locks that child for the launch. Never retry that ID; start a fresh child and provide the required context.
- Every admitted resume clears the child's prior preflight. The resumed child must complete a full new one-step `remote_status` preflight before project tools and before successful registry release. Exact model continuity is not promised.
- The package defaults `remote_status` to `ask` only when neither global nor configured `explore` policy explicitly matches. Stable global/per-agent policy is supported. Only `external_directory` offers reusable `always`: exact normalized path plus descendants for the current OpenCode process. External paths containing literal `*`, `?`, or `\\` are rejected because OpenCode cannot represent those POSIX names literally. Other package permissions have no reusable patterns.
- Task security epochs consume both event pairs: OpenCode v2 `permission.asked` followed by `permission.replied` carrying `requestID`, and legacy `permission.updated` followed by `permission.replied` carrying `permissionID`. Malformed or unknown relevant delivery invalidates fail closed, while the fire-and-forget permission event hook remains non-throwing.
- OpenCode 1.18.18 does not inherit parent session asks into Task children. A matching root-session SSH-project `ask` makes package Task delegation fail closed; direct users to global/per-agent policy and do not claim general parent session `allow`/`ask` inheritance. Package validation preserves inherited deny arrays, but an OpenCode instance-wide external-directory `Allow always` can supersede a matching global, per-agent, or session deny until process exit.
- Read-only siblings may overlap. Mutation-capable siblings require disjoint path scopes; shared mutation transactions serialize, and same-path concurrent editing is unsupported. Conflict and lock checks are backstops, not sibling scheduling.

## Compatibility Preflight Contract

- The canonical description is [`docs/installation-and-usage.md#automatic-compatibility-preflight`](docs/installation-and-usage.md#automatic-compatibility-preflight). Keep it synchronized with `src/opencode-compatibility.ts`, `src/opencode-probe.ts`, and the pre-SSH ordering in `src/cli.ts`.
- This is a focused behavioral startup probe, not the full test suite. Every real launch runs it without caching before launch paths or the SSH ControlMaster are created.
- Probe protocol v3 requires the actual selected OpenCode to resolve the production package root, call the server plugin, register its hooks, invoke the private `config` hook, and atomically publish a nonce-bound marker recording loader runtime version, observation source, and callable `client.session.get`. The selected `--version` must exactly match that runtime version. Missing lookup or malformed/mismatched runtime evidence blocks startup before launch paths, ControlMaster, or SSH; a version check or direct module import alone is not equivalent.
- The probe must remain independent of a remote target, SSH configuration, providers, normal OpenCode/project configuration, and user plugins. Preserve npm registry/proxy/CA transport settings needed for OpenCode to initialize its generated plugin dependencies.
- The marker is the loader success boundary; the diagnostic child is intentionally terminated afterward instead of delaying startup for unrelated `debug config` shutdown work.
- The target-free v3 marker is pre-SSH. In normal production initialization, after the launcher has started the ControlMaster and canonicalized the workdir, the plugin rechecks callable `client.session.get` and matching runtime health through the host SDK's configured transport before claiming launch ownership, creating the mirror, opening the package SSH pool, running bootstrap SSH, or publishing ready. This second check does not precede all SSH because ControlMaster startup and workdir canonicalization already occurred.
- OpenCode 1.18.18/1.18.23 expose a legacy client without public `client.global.health`. Runtime observation prefers that API if future callable; otherwise it requires one shared own `_client` transport on root/global/session and calls `_client.get({ url: "/global/health" })`. SDK envelopes require real `Request`/`Response` objects and exact healthy/version shape. It never raw-fetches `PluginInput.serverUrl` or trusts fallback localhost:4096.
- The target-free compatibility probe runs actual `debug config` and does not invoke TUI, a model, Task, or SSH. Upstream's default no-argument TUI design uses OpenCode's configured in-process SDK transport; the production launcher starts that normal TUI, while its plugin recheck uses the host SDK transport without itself invoking a model, Task, or permission UI or certifying visual TUI behavior. Automated release evidence directly covers target-free `debug config` plus decoys and a hermetic SDK path, not default no-argument TUI; serve evidence is listener-backed. Production has no executable fallback. Only the target-free probe may use strict `process.execPath --version`, and only when no actual health transport exists; an available transport failure or malformed response remains fatal.
- Config calls are validated as a batch before one ready publication. Config failure and disposal are terminal, pool closure starts immediately on disposal, and the launcher re-reads the nonce-bound ready marker after a 25 ms stability interval. Ready proves that startup boundary, not perpetual plugin liveness.
- Formal direct-subagent release remains incomplete only for real-SSH two-sibling mutation and real permission-UI/direct-child TUI evidence. The final exact 1.18.18 baseline passed its six Task scenarios plus the installed permission-engine scenario on 2026-08-28; loader or fake-transport evidence does not close the two remaining real/manual boundaries.
- Changes to this contract require the focused compatibility/probe/lifecycle tests, the actual installed OpenCode loader integration, package-install smoke coverage, `npm run lint`, and the complete default `npm test` gate.

## Startup Diagnostics

- `src/logger.ts` is the reusable best-effort privacy-safe JSONL logger. It defaults to `${XDG_STATE_HOME:-$HOME/.local/state}/opencode-ssh/logs/opencode-ssh-YYYY-MM-DD.jsonl` and uses one file per UTC day. There is no background retention timer: logging activity may run pruning at most once per UTC day per logger instance, and that maintenance keeps the current UTC day plus the previous four. Stale matching files can remain when no later logging occurs. The logger enforces private directory/file modes, caps records at 64 KiB, and gives callers a 500 ms local-I/O deadline. Native filesystem work can finish after that deadline on pathological or non-local filesystems; never claim cancellation or universal bounded process settlement. Logging failure never replaces the core result.
- Current structured instrumentation is startup-focused: compatibility version/probe, launcher SSH/canonicalization/OpenCode/ready/cleanup and bounded host-stderr byte counts/status/truncation, probe health/marker, and production plugin lookup/health/source/version/mirror/pool/bootstrap/config/ready/disposal. Narrow runtime signals are one anonymous `plugin.task_root_permission.normalized` warning at most once per launch; the first 64 classified Task resume admission/registration/completion failures with one limit warning; the first 64 external-directory request/reply/repeat-after-always lifecycles with one limit warning; the first 64 classified ControlMaster stderr messages with one limit warning; and the first 64 failed package SSH/SFTP transports with one limit warning. Resume failure records contain only runtime version and bounded stage/reason enums. Transport records contain only the top-level operation category, transport, bounded reason/failure enums, exit/termination state, and truncation booleans; successful operations, raw OpenSSH lines, and internal channel numbers are not logged. OpenSSH does not expose a stable channel-to-slave mapping, so correlate candidate failures only by timestamp and non-secret `startupID`, then `launchID`/`targetID`, without claiming one-to-one attribution under concurrency. `targetID` is the stable pseudonymous SHA-256 of alias plus canonical workdir; it is not secret or claimed irreversible against guessed inputs. Structured JSONL uses stable failure codes and allowlisted fields and contains no raw host-stderr bytes or path, raw target alias/canonical workdir or project/local paths, commands/argv, environment/config, nonce/token/credential values or their hashes, session/task/permission IDs, output/bodies, or model/provider data.
- Raw OpenCode host stderr is the deliberate unredacted exception to JSONL privacy. The binary prefix can contain credentials, tokens, paths, project/provider/model content, arbitrary bytes, ANSI/OSC controls, and invalid UTF-8. Never `cat`, casually attach/share, or put it in a model, remote child, or project context; inspect locally with a control-safe representation such as `hexdump -C -- <file>`.
- Raw directories/files use `0700`/`0600`. Retention prunes only strict matching regular files older than the current-day-minus-four boundary; future-dated files, malformed names/dates, symlinks, and directories are preserved. Stale files can remain, deletion is not secure erasure, and there is no total storage bound. Capture has no PID/source attribution or write-boundary guarantee and is not universal process-tree settlement evidence; forced closure can lose unread buffered bytes or a direct-host/descendant tail.
- OpenCode stdout remains inherited and uncaptured. Stdout, `/dev/tty`, unrelated same-terminal writers, and input/mouse corruption can still affect the TUI. Host stderr is not a TTY and `process.stderr.isTTY` is falsy, commonly `undefined`, which can alter color/progress or hide third-party stderr prompts. Keep raw host capture distinct from privacy-safe ControlMaster line classification and failed package SSH/SFTP result classification.
- Future instrumentation should import `createFileLogger` from the relative `./logger.js`-style NodeNext path, use stable names matching `[A-Za-z0-9][A-Za-z0-9._:-]*`, and pass only reviewed non-secret fields. Critical cleanup/disposal must start before awaiting diagnostics. Do not expand the documented narrow runtime diagnostics into general successful project, tool, permission, session, or model telemetry.
- On launcher failure, report the local structured-diagnostics path and `startupID` only after at least one successful write. The path is operator-facing local troubleshooting data, not a value to place inside log records or remote-child workflow.

## Configuration And SSH

- SSH aliases are passed unchanged to system OpenSSH, so `~/.ssh/config`, `known_hosts`, keys, `ssh-agent`, encrypted-key prompts, and `ProxyJump` remain authoritative.
- Master startup disables account-password and keyboard-interactive fallback but allows host-key and private-key passphrase prompts. No password or sudo askpass support exists.
- Activation requires the complete private launcher environment and matching plugin tuple `launchID`. Without it, the plugin is dormant.
- Same-process plugins, direct SDK/session API callers, and same-UID local processes are trusted TCB members. A colliding enabled `mcp.remote` config is rejected; hostile trusted plugins, SDK calls that bypass package-observed Task hooks, and duplicate module instances are not sandboxed.
- Global OpenCode config, provider environment, plugins, and MCP remain available. Caller-directory project config is not discovered because OpenCode starts in a stable target-specific local workspace.
- Stable session identity and logged `targetID` are based on the SHA-256 of alias plus canonical workdir. This is pseudonymous correlation, not secrecy against guessed inputs. Mirrors are launch-specific and removed during launcher cleanup.

## Permissions And Paths

- Remote paths reject control characters and are canonicalized with remote `realpath -e` before access. Missing mutation paths canonicalize their nearest existing ancestor.
- Canonical paths outside the configured workdir request `external_directory` permission. A workdir of `/` contains every absolute remote path.
- `external_directory` offers process-local `Allow always` for the exact normalized path and descendants. OpenCode shares that approval across sessions in the current process; it does not survive restart and does not approve `read`, `glob`, `grep`, `edit`, or `bash`. External paths containing literal `*`, `?`, or `\\` are rejected.
- `read`, `glob`, `grep`, `edit`, and `bash` use their corresponding OpenCode permission checks. Arbitrary paths embedded inside shell text cannot be inferred reliably and remain governed by the bash permission.
- `remote_status` requests its own OpenCode permission before its fixed identity SSH command. That permission does not grant arbitrary Bash. Explicit `ask`/`deny`, current-session policy, primary-tool restrictions, and restrictive custom-agent policy apply to that session; Task-child inheritance has the 1.18.18 limitation above. A child without package `remote_status` must stop.
- Package project tools reject before preparation when preflight is incomplete. After preflight, path canonicalization and write/edit/patch baseline pulls may precede the tool-specific `bash`/`read`/`edit` prompt; mutation remains after approval. Lexical external paths ask before canonicalization, and a different canonical external target receives a separate check.
- After `read` approval, positively identified PNG, JPEG, GIF, and WebP files up to 3 MiB are returned as OpenCode attachments. Canonical path, size, and signature are checked around SFTP, and the temporary size is checked before loading into memory; this is not a hard SFTP transfer, transient-path-race, or decoded-memory bound. Attachments may persist in OpenCode session state and reach the configured image-capable provider after mirror cleanup. SVG, PDF, BMP, and other binaries remain unsupported.
- Each bash call is a separate POSIX `sh` process; `cd` does not persist.
- SFTP operations run with the SSH user's privileges. Root-owned files require explicit reviewed `sudo -n` shell commands.
- `apply_patch` add/update are supported. Delete and move are rejected until dedicated atomic implementations exist.

## Implementation Traps

- This is strict NodeNext ESM. TypeScript source imports local modules with `.js` suffixes.
- Never use `shell: true`, interpolate aliases into local command strings, or automatically retry a command after spawn.
- OpenSSH SFTP batch quoting differs from shell quoting. Keep glob characters escaped and reject CR/LF/NUL paths.
- Remote lock directories fail closed when stale. Do not auto-delete an unknown lock during a mutation.
- File conflicts are content-checked under cooperative plugin locks. Non-cooperating remote processes can still race after the final validation; never overstate this as a universal filesystem transaction.
- File replacement preserves content and numeric mode only. New files are `0600`; owner/group/ACL/xattr/capability/timestamp/hard-link identity are not preserved. Multi-file commits are per-file atomic and typed partial results distinguish committed/failed/uncertain/unattempted paths.
- One active factory is enforced only per loaded module and launch ID. Pool close aborts and settles active SSH/SFTP slaves through its own closure path. POSIX process groups cover only owned local launcher children that explicitly request them: OpenCode, version, and compatibility-probe processes. Do not claim every local child is in a process group, hostile module-instance protection, or universal real-remote descendant termination.
- The root must wait for every fresh and resumed run to settle, recheck remote status and changed paths/diff after resumed work, and report every child/run change, failure, cancellation, and uncertainty. Resume settlement does not prove settlement of real remote descendants. Do not claim recursive delegation or same-path sibling mutation support.
- Automated cancellation coverage proves local OpenCode Task/session settlement, local SSH slave termination, and no retry under fake SSH. It does not prove universal termination of real remote descendants.
- The package requires Node.js 22.22.2+ and retains OpenCode 1.18.18 as the exact regression baseline. Another identified version must pass the loader and production runtime checks and receives an advisory warning; passing versions receive Task resume capability, while an unidentified or mismatched version is blocked.
- The supported remote is GNU/Linux with SFTP, POSIX `sh`, `hostname`, `whoami`, `pwd -P`, startup utilities, GNU `realpath -e --`, `stat -c`, `mv -fT --`, and the documented read/search fallbacks. `head` is no longer a startup requirement because remote `AGENTS.md` is not loaded. Recorded local hardening evidence is Linux x86_64; do not imply tested macOS-remote support.
- `package-lock.json` is tracked. Do not run `npm audit fix --force` or change pinned dependencies without reviewing the lock diff.
- Never edit ignored `dist/` as source. Change `src/` or build scripts and run a full build.
- Tracked examples and documentation must never contain connection details or credentials.
- Dated implementation plans are historical records, not current instructions; use the source, tests, README, and security documentation as authoritative behavior.
